<objective>
Close the phase on measurements rather than impressions.

Three of the six ROADMAP criteria are about the tree as a whole rather than
about either retailer: no regression, a pass still inside two minutes, and a
count somebody can check. All three are answered by running things and reading
numbers off them, and all three are easy to answer wrongly by feel.

**Criterion 3 as amended asks for five or more retailers with no health
warnings — six if Amazon lands.** Target is the fifth, registered at rung 3 with
DOM extraction and **control-only**, because it delisted the GO Plus + (TCIN
`88714054`, HTTP 200 as late as 2025-05, now 404). That is worth stating in the
same breath as the count: five retailers is a real five, and one of them can
never alert on the product. Read the ROADMAP's own wording before writing
anything about it: *"Five is the honest ceiling when Amazon is technically
unreachable, and criterion 2 explicitly permits that. Do not raise the target to
six: a gate that fires on the honest outcome is the Phase 2 rot in the opposite
sign."* So on the expected outcome — Target lands, Amazon walls — the criterion
is **met at five**, and the arithmetic that gets there is an explanation rather
than a confession. Filing that as a shortfall would write a false record into
three documents and escalate a settled question to Dan.

The criterion still has a real failure direction, and this plan measures both
halves of it: fewer than five configured retailers fails it, and so does any
health warning — a permanently-UNKNOWN retailer satisfies a count while failing
the criterion outright, which is why `healthy` is asserted at the same moment
the duration is read.

Purpose: turn the phase's whole-tree criteria into recorded numbers, and put the
count on the record honestly whichever way it fell.
Output: a verified tree, a measured pass duration, and documentation that agrees
with `config/products.yaml`.
</objective>

- The browser environment lives in the **service's** `EnvironmentFile`, not in
  any shell. Verifying with `env -i` strips it and produces a false red. The
  correct incantation is:
  `sudo systemd-run --pipe --quiet --uid=dan --property=EnvironmentFile=/home/dan/.config/boty/env --property=WorkingDirectory=/home/dan/CodeProjects/pokemongoplusplus /usr/bin/make verify`
- `scripts/control_check.py` has four outcomes, not two: 0 pass, 1 fail,
  `SKIPPED=3` (no outbound connectivity), `INCOMPLETE=4` (some controls could
  not run **on this host** — the browser extra or a Chrome binary is missing).
  `make verify` maps 3 and 4 to `VERIFY: PASS (OFFLINE — …)` and
  `VERIFY: PASS (INCOMPLETE — …)`. An INCOMPLETE verdict is not a green for the
  criterion "the four Phase 2 retailers still green": it means a detector was
  never reached. Record which verdict line was printed.
- `boty.status.write` publishes `duration_seconds`,
  `healthy: all(h.ok for h in health)`, and — since 03.1-05 — per-watch `rung`,
  `extraction` and the derived `degraded`, into `served/boty/status.json` on every
  `check` and every service cycle, and `cli.main` prints the same `elapsed` as
  `check`'s last line. Phase 3 recorded 61.4 s for a manual pass and 35.0 s from
  the service's own next cycle, at 10 watches across 4 retailers with one on
