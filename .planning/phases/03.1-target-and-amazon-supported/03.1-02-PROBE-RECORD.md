# Phase 3.1 Plan 02: Register Target Summary

**Target was probed for the first time in this project's history, on the path its own robots.txt publishes, and it neither refused us nor gave us anything: three product pages returned HTTP 200 with no challenge, no block phrase and `"isBot": false` — and zero price, zero availability and zero seller, because Target renders all of it from an API host it closes to every agent.**

## Outcome: Target is NOT registered, and that is an escalation, not a choice

The plan was written on the expectation that this would work, and said plainly:
*"There is no branch in this plan where Target ends unregistered by choice."* It
also defined the one branch that is not a choice — a technical wall — as **a
phase-level escalation to Dan**. That is the branch the tree landed on, in a
shape the plan did not anticipate.

**Dan's decision was not relitigated, revisited or hedged.** The Terms of Use
reasoning is gone from Target's conclusion and is not coming back. What stopped
this is not the terms.

## What was found

### Target did not refuse us — that is the surprise

Two live control-candidate PDPs and one brand page, all through `boty.fetch.get`
so `BLOCK_PHRASES` was in front of every byte:

- `/p/microfiber-dust-cloths-6pk-up-38-up-8482/-/A-90377926` — **HTTP 200**, 314,757 B
- `/p/premium-plastic-spoons-48ct-up-38-up-8482/-/A-89685884` — **HTTP 200**, 318,690 B
- `/b/pokemon-go/-/N-q643lez1n7g` — **HTTP 200**, 138,984 B

**No `BLOCK_PHRASES` entry matched on any of them** — not the two Akamai markers
Phase 2 added *specifically because Akamai fronts Target*, not Imperva. Target's
own page data reads `"isBot": false, "isAiAgent": false`. We were served the
ordinary page that every visitor gets.

### And the ordinary page has no product data on it

Measured across the whole 314,757-byte document:

| Signal | Occurrences |
|---|---|
| `application/ld+json` | **0** |
| `schema.org` | **0** |
| `"price"` | **0** |
| `availability` (any case) | **0** |
| `"seller"` | **0** |
| `InStock` / `OutOfStock` / `current_retail` | **0** |
| `<meta property="og:type" content="product">` | 1 — the only product metadata present |

The price module ships as an empty hole —
`{"module_type": "ProductDetailPrice", "module_data": {}}` and
`data-test="price-module-placeholder"` — and Target's own flag says so:
`"isProductDetailServerSideRenderPriceEnabled": false`.

**That flag is why this was probed twice.** A feature flag can be cohort-based,
and a cohort-based wall falls on a retry. A second, unrelated PDP gave the
identical result, and archived snapshots from **2023-05** and **2025-05** carry
no `ld+json` either. The wall is structural and long-standing.

`_verdict_from_html` would therefore read this page perfectly and return
`UNKNOWN — "no structured stock data found (page shape changed?)"` forever. The
UNKNOWN contract working exactly as designed, on a detector that can never detect.

### The sitemap is not the index it looks like

The PDP sitemap was expected to solve the TCIN-discovery problem Phase 2
abandoned Target over. **It cannot, for a structural reason rather than a budget
one.** The 110 shards are sorted by TCIN *as a string* in **two independent
runs** — shard `20-0001` opens at the lexicographic minimum (`1000000074`) while
`19-0003` closes at the maximum (`9999999350`). Excellent for looking a *known*
TCIN up; useless for finding a product by *slug*, which has no locality and would
need all 110 shards (~900 MB).

The brand sitemap looked like a shortcut and was not: `/b/pokemon-go/` exists,
reads cleanly, and carries zero product TCINs — its grid loads from RedSky.

### Every general search engine refused the fallback; the Internet Archive did not

The plan's public-source fallback was genuinely attempted:

| Source | Result |
|---|---|
| `html.duckduckgo.com` / `lite.duckduckgo.com` | HTTP **202** challenge |
| `ecosia.org` | HTTP **403** |
| `search.yahoo.com` | HTTP **500** |
| `reddit.com/search.json` | HTTP **403** |
| 5 SearXNG instances | 1 anti-bot interstitial, 4 × HTTP **429** |
| Bing, Google, DuckDuckGo via headless Chrome | CAPTCHA on all three |

**`web.archive.org/cdx/search/cdx` answered it** — a public index that exists to
be queried and costs Target nothing. It also revealed that **Target encodes `é`
as `-233-`**, so the real slug is `pok-233-mon-go-plus`; no guess at
`pokemon-go-plus-plus` would ever have hit it.

## Issues Encountered

**The seller-string hazard could not be closed, and that is the one thing this

at all**. The entry stays dormant and unreachable — nothing dispatches a Target
watch — but its status has changed from *unverified* to *known unverifiable from
`/p/` HTML*, which is a materially more useful thing to have written down.
