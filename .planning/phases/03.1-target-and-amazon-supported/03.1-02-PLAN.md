<objective>
Register Target, on the path its own `robots.txt` publishes.

**This is expected to work, and the plan is written on that expectation.**
`www.target.com/robots.txt` has one `User-agent` group, no named-bot blocks, and
does not disallow `/p/` — the only `/p/` rule in the file is
`/p/premium-registry`. Target publishes `sitemap_pdp-index.xml.gz`, a
product-detail index that exists to be crawled and that is the answer to the
TCIN-discovery problem Phase 2 abandoned Target over. Phase 3 recorded all of
that and then did not walk it.

The decision to walk it is Dan's, taken 2026-08-03, and it is settled: *"bot-y
is a bot for humans. To take the power back from other bots."* Nothing in this
plan re-reads Target's Terms to decide whether to proceed. Phase 3's evidence —
every byte count, every quoted clause, the RedSky `Disallow: /` — is real and
stays in the document. What this plan rewrites is the conclusion drawn from it,
and it says so in the evidence log rather than quietly editing a verdict line.

**There is no branch in this plan where Target ends unregistered.** The only
outcome that is genuinely open is whether Target *lists* the Pokémon GO Plus + —
a fact about Target's catalogue, settled the same way Best Buy's was, by
searching and recording the result. A control watch and a green control are not
optional either way.

Purpose: the fifth retailer, read from the page its robots.txt invites, with the
seller-string hazard that has sat dormant in `boty/retailers.py` since before
this project ever probed Target finally closed by observation.
Output: a Target adapter path, a fixture, a green control, a rewritten verdict,
and a guard that tells the truth on the branch the tree is now on.
</objective>

<interfaces>
Contracts this plan works against:

- `boty.fetch.get(url) -> Page` raises `Blocked` when the body matches any
  `BLOCK_PHRASES` entry — which already includes the two Akamai markers
  (`sec-if-cpt-container`, `scf-akamai-protected-by`) added in Phase 2
  *specifically because Akamai fronts Target*. A Target wall must surface as
  `Blocked`, not as "page shape changed?". **Do not add `datadome`**: real
  product pages reference DataDome assets while serving genuine content.
- `boty.parse.ldjson_offers(html, *, sku=None) -> list[Offer] | None` and
  `boty.parse.nextdata_offers(html) -> list[Offer] | None`. Both return `None`
  when the source is absent. `Offer` is `(available, price, seller, raw_availability)`.
- `boty.retailers._verdict_from_html` tries `ldjson_offers` first, then
  `nextdata_offers`. `target` is in `MARKETPLACES`, so `_pick`'s
  unattributed-offer fallback is disabled for it: an offer whose seller is not
  in `FIRST_PARTY['target']` produces `OUT_OF_STOCK`, not `UNKNOWN`.
- `boty.cli._make_checker` is the one place a watch is matched to a transport.
  A URL-addressed rung-1 retailer needs no branch there (the Nintendo shape). A
  rung-3 retailer needs one (the Best Buy shape) and must return
  `rung=Rung.BROWSER` on every path including the error paths.
- `.venv/bin/boty capture-fixture <retailer> <name> <url> --note '<state>' [--browser]`
  writes `tests/fixtures/<retailer>/<name>.html` plus a `.json` sidecar, and
  refuses to write anything for a blocked fetch.
- `tests/test_retailers.py` carries the Target guard at lines ~1091-1544:
  `_target_verdict`, `_target_disagreements` (a REFUSED branch and a REACHABLE
  branch), `test_the_target_verdict_and_the_shipped_tree_agree`,
  `test_the_dormant_target_allow_list_entry_is_documented_as_a_guess`,
  `_flip_only_the_anchored_target_verdict` and its `count(_REFUSED) == 2`
  assertion, and four tests that drive each branch.
- `scripts/mutation_check.py` M2 anchors on the exact substring
  `Availability.UNKNOWN,\n            detail="no structured stock data found`
  in `boty/retailers.py` — twelve spaces of indentation. M3 anchors on
  `if first_party_only:`. Any edit near those must leave them byte-identical.

**Step 1 — discover the TCIN.**

Fetch `https://www.target.com/sitemap_pdp-index.xml.gz` (one request). Decompress

whatever ordering or naming signal the index gives; grep each for

that is both expensive for Target and outside the budget.

If four shards do not find it, fall back to a **public source that is not
target.com** — a web search, a shopping aggregator — for a candidate TCIN, then
verify it with a single `/p/` fetch. Record which route produced the TCIN. This
fallback costs Target nothing and exists so criterion 1 cannot fail on a
discovery technicality.

were fetched, which terms were grepped, and what came back. That is the Best Buy
shape — a finding, not an omission — and it changes only whether a GO Plus +
watch ships. It does **not** change whether Target is registered.

**Step 2 — choose a control candidate.**

Per the rules already written into `config/products.yaml`: first-party,

Good & Gather, Up&Up, Market Pantry, Threshold. Not a console, not a Pokémon
product, not a limited drop. Prefer something that ships rather than a
store-only grocery line, because a store-only item can read out-of-stock online
while the detector is working perfectly. At most **3** candidates, inside the
same 12-request budget.

**Step 3 — read the pages.**

Fetch the GO Plus + page (if found) and the control candidate through

`BLOCK_PHRASES` in front of Target's bytes. Save the response text to the
scratchpad directory, **not** to `tests/fixtures/`.

**Step 4 — record.**
