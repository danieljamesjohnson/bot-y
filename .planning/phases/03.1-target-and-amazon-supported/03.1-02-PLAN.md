<objective>
Register Target on rung 3 with DOM extraction — control-only.

**This plan is a rewrite, and what it replaces is a finding rather than a
failure.** 03.1-02's first execution probed Target for the first time in this
project's history and established something nobody knew: Target does not refuse
us. Three product pages returned HTTP 200 at rung 1, ~315 KB, correct titles, no
challenge, no `BLOCK_PHRASES` match, `"isBot": false`. And the pages carry
**zero** structured data — no `ld+json`, no schema.org, no price, no
availability, no seller — because Target ships the price module empty
(`isProductDetailServerSideRenderPriceEnabled: false`) and renders stock from
RedSky client-side. Confirmed across two unrelated PDPs and 2023/2025 archive
snapshots: structural, not a cohort flag. That summary and commit `c79e8ce` are
the basis of everything below.

Two consequences carry into this rewrite and neither is negotiable:

- **`FIRST_PARTY['target']` is known *unverifiable* from `/p/` HTML**, not merely
  unverified. There is no `offers.seller.name` on the page to read. This plan
  does not widen it against a live string, because no such string exists; it
  decides deliberately what the entry should mean given a DOM adapter, and says
  so in the evidence log.
- **Target no longer lists the Pokémon GO Plus +.** TCIN `88714054` served HTTP
  200 as late as 2025-05 and now 404s. Target can therefore only ever be a
  **control-only** retailer, the Best Buy shape. Do not plan a GO Plus + watch.

What changed is the method. Dan's original pre-bot-y script — `undetected_chromedriver`
plus Selenium — decided stock from the **Add to Cart button**: its text against
`["add to cart", "preorder", "pre-order"]`, and whether it was enabled. It never
touched Target; it read GameStop and Walmart. But its method is exactly what
Target needs, because Target renders the button even though it ships no
structured data. Dan wants that method supported, on the second axis 03.1-05
built: rung 3 (transport) + dom (extraction), and therefore `degraded`.

Purpose: the fifth retailer, read the only way its page can be read, with the
fragility of that method declared in the matrix rather than hidden behind a rung
number it shares with Best Buy's `ld+json`.
Output: a DOM reader with its own mutation, a Target adapter, a green control, a
revised verdict, and a matrix row that tells a reader what a Target reading is
worth.
</objective>

**1. Add the DOM reader to `boty/parse.py`.** Stdlib only — use `html.parser`,
**add no parsing dependency**. Model it on the two existing readers: it returns
`list[Offer] | None`, and `None` means "the signal this reader looks for is not
on this page", which the caller turns into UNKNOWN.

Name the add-to-cart phrases as a module constant, taken from Dan's original
script: `("add to cart", "preorder", "pre-order")`, matched case-insensitively
against the control's visible text. Availability is **matched text AND not
disabled** — a rendered button carries `disabled=""` when React disables it.

The three behaviours Task 1 measured decide the rest, and each one must be
written the way the observation says rather than the way the code is convenient:

- **Control absent** → return `None`. Never an empty list, which reads as "a
  product with no offers", and never `available=False`, which would report
  out-of-stock for a render that failed. If Task 1 found that Target *removes*
  the button when unavailable, then an explicit out-of-stock marker is the only
  thing that may produce `available=False`, and its absence together with the
  button's absence is still `None`.
- **Price** → read from the element Task 1 recorded; `None` if unreadable. An
  unreadable price does not block a verdict, but `Result.alertable` already
  refuses to clear a ceiling on a `None` price, so the safety property holds.
- **Seller** → if a "sold and shipped by" partner block is present, the offer's
  seller is that partner's name, verbatim. If it is absent, the item is sold by
  Target itself.

**2. Decide `FIRST_PARTY['target']` deliberately, and write the decision down.**

There is no `offers.seller.name` on a Target page, so there is no live string to
widen the allow-list to. But `target` is in `MARKETPLACES`, which disables
`_pick`'s unattributed-offer fallback — so an offer with `seller=None` reads
UNKNOWN forever and the control can never go green. That is the interaction to
resolve, and the resolution must keep a Target Plus partner listing from ever
alerting.

Take this shape: when no partner block is present, the reader emits the literal
`"target"` as the seller, and `FIRST_PARTY['target']` stays `{"target"}` — but
its meaning changes and the comment must say so. It is no longer a guess about
Target's markup; it is a statement about **our own reader's output**, and the
claim underneath it is *"absence of a partner block on a Target PDP means Target
is the seller"*. That claim is checkable, it is recorded in the evidence log, and
it is what the partner-block test below pins. `target` stays in `MARKETPLACES`.

Do not remove `target` from `MARKETPLACES` to make the seller problem go away —
that re-enables the unattributed fallback and lets a Target Plus reseller listing
alert, which is the flipper case the whole first-party filter exists for.

**3. Wire it into `_verdict_from_html` as an opt-in third reader.** Add a
keyword-only `allow_dom: bool = False`. When true, and both structured readers
returned `None`, try the DOM reader; if it produces offers, the verdict carries
`extraction=Extraction.DOM` and a `source` label naming the DOM reader so the
`detail` string says which reader produced it. When the structured readers
succeed, the extraction stays `STRUCTURED`.

Opt-in rather than universal, deliberately: a GameStop page that lost its
`ld+json` would otherwise silently fall through to a DOM read, changing an
existing retailer's behaviour without anyone deciding to. Every existing adapter
keeps its behaviour byte-identical.

**Do not disturb M2 or M3.** M2's anchor is the `Availability.UNKNOWN,` /
twelve-space / `detail="no structured stock data found` return, and M3's is
`if first_party_only:`. Add the DOM attempt **before** that return without
reindenting or rewording it. If the dom-enabled path wants a different diagnosis,
add a separate `return` above it rather than editing that one.
