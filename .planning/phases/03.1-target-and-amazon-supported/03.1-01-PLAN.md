<objective>
Move both gates before either retailer moves.

Phase 3.1 registers Target and Amazon. Two mechanical things must be true before
that happens, or the phase lands its retailers against gates that cannot see
them:

1. **W-02 is open.** `scripts/evidence_check.py` has a floor (rule 4: *a refusal
   cannot outrank a capture*) and no mirror. A tree that configures a retailer
   while its own evidence log records `**Verdict: REFUSED**` returns
   `evidence check: PASS — phase`, exit 0. `03-VERIFICATION.md` proved that by
   execution. Registering Target against a standing REFUSED is exactly that
   shape, and it must be the gate that catches it — not
   `test_no_retailer_is_configured_without_a_page_we_have_actually_read`, which
   catches it today only by accident of Imperva blocking a fixture capture.

2. **REQ-13 does not exist yet.** The support matrix has four columns and states
   only a rung. REQ-13 wants every row to state its rung, its robots.txt
   position on the path used, and its terms position, so a reader sees the
   disagreement rather than only the verdict it resolved to. That has to be
   machine-checked the way every other matrix rule already is, or it is prose
   nobody enforces.

Doing both here means the Target and Amazon plans land into a tree whose gates
already demand the truth, instead of one where the gate is edited to fit the
outcome afterwards.

Purpose: make the two remaining honesty gaps mechanical before the retailers
that would exploit them arrive.
Output: rule 5 in the honesty gate, a seven-retailer robots/terms record in the
evidence log, and a six-column support matrix with rules that fail in both
directions.
</objective>

The rule: for each entry of `ROADMAP_RETAILERS` that IS in `configured`, look up

  is heading for.

  ("two records of one retailer means nothing here can tell which is current")

retailer, and say which way the contradiction points. Something of the shape:
"rule 5 (a configuration cannot outrank a refusal): {config_path} configures
{retailer!r} while {evidence_path} records `**Verdict: REFUSED**` for {display}.
Rule 4 stops a refusal outranking a capture; this is its mirror. A tree that
ships a detector for a retailer it has written down as refused is telling two
stories, and the honest edit is whichever one is now false — flip the verdict
and say why in the same commit, or drop the watch."

The two new cells take a fixed vocabulary, because a cell nothing can parse is
prose nobody enforces:

- the robots.txt cell begins with `permits`, `disallows` or `silent on`, and
  contains the path in backticks — e.g. ``permits `/p/` `` or
  ``disallows `/cortex/…` ``;
- the Terms cell begins with `forbids`, `permits` or `silent` — e.g.
  `forbids extraction`.

A row whose two positions point in opposite directions carries the literal
marker `⚠ disagree` in its Status cell, and a row whose positions agree does
**not**. That marker is the whole of REQ-13's "a reader sees the disagreement":
Target's row must show that its robots.txt publishes a product sitemap and
permits `/p/` while its terms forbid extraction, and must show it in the table
rather than only in the evidence log.

Update the prose under the table that describes what the matrix guarantees, so
it names the three things every row now states and says where the positions come
from. Do not delete the existing paragraphs about the ceiling, the floor and the
UNPROBED third state — they are still true and the tests still reference them.

**tests/test_support_matrix.py.** Update the parser constants and add the rules.

Change `HEADER_CELLS` to the six-cell header and the column constants to
`RETAILER, RUNG, ROBOTS, TERMS, METHOD, STATUS = 0, 1, 2, 3, 4, 5`. Everything
that indexes by name keeps working; `_corrupt` takes a column index and needs no
change.

Add two module constants stating the vocabularies as tuples of accepted
prefixes, and two rule functions in the same style as `_rungless` and
`_overstated` — functions over parsed rows, so the corruption tests can run the
same rule against a deliberately broken copy of the real README:

- `_positionless(rows) -> dict[str, tuple[str, str]]` — every roadmap retailer
  whose robots cell or terms cell does not begin with an accepted prefix.
  Blank, `TBD`, `n/a` and free prose all fail.
- `_misdeclared_disagreement(rows) -> list[str]` — every roadmap retailer where
  the presence of the literal `⚠ disagree` anywhere in the row does not match
  whether the two positions actually disagree. Treat `permits` and `silent` as
  permissive on both sides and `disallows` / `forbids` as prohibitive;
  disagreement is exactly one side prohibitive.

`_misdeclared_disagreement` is deliberately two-directional and that is the
point: a rule of the form "every row must say `⚠ disagree`" is satisfied by
pasting the marker into all seven rows, which states nothing. This one goes red
for a marker that is missing *and* for one that is not earned.

Add tests against the shipped README — `_positionless` empty,
`_misdeclared_disagreement` empty — and corruption tests using `_corrupt`,
each watched failing:

- blanking Target's robots cell → `_positionless` names Target;
- setting a Terms cell to `TBD` → `_positionless` names that retailer;
- stripping `⚠ disagree` from Target's Status cell → `_misdeclared_disagreement`
  is `["Target"]`;
- adding `⚠ disagree` to a row whose positions agree → `_misdeclared_disagreement`
  names that row. If no shipped row has agreeing positions, build the case by
  corrupting one row's robots cell to `disallows \`/x\`` first and assert the
  marker then has to come off — the rule must be watched failing in this
  direction even if today's tree gives it nothing to bite.

Also assert the header itself: a test that `_matrix()` finds a table whose header
is exactly the six cells, so moving a column silently is a red test rather than
a quiet reindex.
