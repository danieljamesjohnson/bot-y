<objective>
Attempt Amazon for real, then record what actually happened.

Phase 3 made **zero** requests to any Amazon product page. That is stated four
times in `docs/retailer-evidence.md` and it is true — so there is no technical
evidence about Amazon in either direction, and the rung-4 verdict rests entirely
on a reading of the Conditions of Use, which Dan reversed on 2026-08-03. What is
left is a question nobody has asked: **can we read the page at all?**

**Two things changed since this plan was first written, and both change what an
answer can look like.**

First, 03.1-02 established Target's shape by measurement: HTTP 200, no challenge,
and a page carrying no structured data at all. That is now a **known outcome**.
If Amazon presents it, it is neither a wall nor a bug in our parser — it is a
retailer that renders its stock state instead of publishing it.

Second, that shape now has an answer. 03.1-05 added the `Extraction` axis and
03.1-02 built a DOM reader that decides stock from the add-to-cart control.
Amazon is in fact the **most likely first consumer of rung 1 + dom**: its
`/dp/` page has historically served a real add-to-cart control server-side, so
impersonated HTTP may reach it without a browser at all. That combination —
cheap transport, fragile extraction — is precisely the one that would have
shipped looking fully trustworthy before 03.1-05 widened `degraded`. It is worth
noticing that the axis was not built speculatively.

Amazon is also the retailer where the seller filter and the price ceiling matter
most: `amazon` is in `MARKETPLACES`, its buy box is frequently held by third
parties, and a GO Plus + at $229 from a flipper is the exact alert this project
exists not to send.

**Every outcome below is legitimate; only one of them is cheap.** A real
technical rung 4 — a wall, observed, at two rungs — is a genuine finding. A rung 4
reached by not trying, or by calling a rendering retailer a refusal, is not. The
line is drawn mechanically rather than left to judgement: the refusal branch
requires three observations across two rungs, rule 6 fails a refusal citing
fewer, rule 4 forbids an unconfigured retailer whose page was captured, and the
registration branch requires a green control line rather than an exit code that
merely is not red.

Purpose: settle Amazon on evidence from an actual attempt, and make "dropped for
a reason that is an observation, not a policy reading" (REQ-07a) a rule the tree
enforces rather than a sentence in a requirements document.
Output: a live Amazon observation, whichever of four shapes it lands on, and a
gate that can tell them apart.
</objective>
