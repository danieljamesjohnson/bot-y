## The rule-5 message, verbatim

The next two plans branch on this text. Emitted by `check_phase` and printed to
stderr by `main`:

```
rule 5 (a configuration cannot outrank a refusal): {config_path} configures
'{retailer}' while {evidence_path} records `**Verdict: REFUSED**` for {display}.
Rule 4 stops a refusal outranking a capture; this is its mirror. A tree that
ships a detector for a retailer it has written down as refused is telling two
stories, and the honest edit is whichever one is now false — flip the verdict and
say why in the same commit, or drop the watch.
```

The UNPROBED variant, same rule prefix:

```
rule 5 (a configuration cannot outrank a refusal): {config_path} configures
'{retailer}' while {evidence_path} still records `**Verdict: UNPROBED (scoped
YYYY-MM-DD)**` for {display}. UNPROBED means nobody has looked yet, and a shipped
detector is somebody having looked — one of the two is stale. Record what the
probe found and give the section a settled verdict, or drop the watch.
```

**Before/after on the identical reproduction script:**

```
before rule 5:   problems: []                      evidence check: PASS — phase   exit 0
after rule 5:    problems: [<the message above>]   evidence check: FAIL — 1 problem(s)   exit 1
```

Rule 5 is silent for a configured retailer with **no section at all** (GameStop and

## The four robots.txt readings, verbatim

**Requests: 7 of 8 budgeted, 16 s apart, no retries.** Every one a `robots.txt` or
a public policy document. No product page, no fixture, no capture.

### GameStop — refused

`https://www.gamestop.com/robots.txt` → **HTTP 403**, 4,572 B, `text/html`. Not a
`robots.txt`: a Cloudflare interstitial titled `Attention Required! | Cloudflare`.

> Sorry, you have been blocked
>
> You are unable to access gamestop.com
>
> This website is using a security service to protect itself from online attacks.
> The action you just performed triggered the security solution.

**Position: `unread`.** The rest of that body is deliberately not transcribed
anywhere — it carried a Cloudflare Ray ID and **this host's public IPv6 address**,
which is the leak that cost this project a whole repository on 2026-08-03. The
terms page was never requested (no-escalation rule).

Worth carrying forward: GameStop serves this repo product pages at rung 1 on every
`make verify` and refused it the `robots.txt` that would say whether it wants to.
The difference is the transport — `curl_cffi` replays a real Chrome ClientHello,
plain `curl` does not.

### Walmart — read

`https://www.walmart.com/robots.txt` → **HTTP 200**, 3,584 B, `text/plain`. One `*`
group. **No rule matches `/ip/`**, the path this repo fetches:

Disallow: /account/
Disallow: /api/
Disallow: /search
Disallow: /orders
Disallow: /typeahead/
Disallow: */api/wpa

### Best Buy — refused, both documents

`https://www.bestbuy.com/robots.txt` → **no HTTP status**, 0 B,
`curl: (92) HTTP/2 stream 1 was not closed cleanly: INTERNAL_ERROR (err 2)`.

### Nintendo — read

`https://www.nintendo.com/robots.txt` → **HTTP 200**, 5,167 B, `text/plain`.

```
User-agent: *
Allow: /
```

Every `Disallow: /` below is scoped to a *named* crawler (`Kangaroo Bot`, `Nutch`,

Disallow: /sg/support/qa-list
Disallow: /my/support/qa-list
Disallow: /th/support/qa-list
Disallow: /ph/support/qa-list

Nothing matches `/us/store/products/<slug>/`, and
`Sitemap: https://www.nintendo.com/us/store/sitemap.xml` is published.
**Position: `permits /us/store/products/`.**

**The same file ends with a prohibition that is not a directive** — four `#`
comment lines reserving all rights and stating that "web scraping, machine
learning, or any form of text or data mining by any means, is strictly
prohibited". Mechanically inert; quoted in full in the evidence log.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The plan's own Task-2 verify command asserts an invariant the tree has never satisfied**

- **Found during:** Task 2
- **Issue:** The inline check requires every roadmap retailer to resolve to
  *exactly* one evidence section (`len(sections_for(d)) != 1` must be empty).
  GameStop and Walmart resolve to **zero** — they have never had a section, which
  is legal and is the first documented allowance of rule 5. The command would have
  failed on the pre-change tree.
- **Fix:** Verified the real invariant instead — at most one section per retailer,
  plus a before/after comparison proving the new heading created no second section:
  `BEFORE (HEAD) {GameStop: 0, Walmart: 0, Best Buy: 1, Pokémon Center: 1, Nintendo: 1, Target: 1, Amazon: 1}`
  and an identical AFTER. Encoded permanently as
  `test_no_roadmap_retailer_resolves_to_more_than_one_section`.
- **Verification:** `evidence check: PASS — phase` exit 0; the new test passes and
  is the only mechanical cover for duplicate GameStop/Walmart headings.
- **Committed in:** `2b621c1` (test), `18c2c65` (section)

**2. [Rule 2 - Missing critical functionality] REQ-13 needed a fourth position word, and a pin to stop it rotting**

- **Found during:** Task 2
- **Issue:** The plan's vocabulary (`permits`/`disallows`/`silent on`;
  `forbids`/`permits`/`silent`) assumes every document gets read. Three retailers
  refused. Writing `permits` or `silent` for a document nobody has read would be
  inventing evidence — and `silent` on the robots side *means permission*, so it
  would have been an actively false claim about GameStop and Best Buy.
- **Fix:** Added `unread` to both vocabularies, required it to name the refusal,
  and made `_disagrees` return `None` when either side is `unread` so an unread
  document can never be half of a disagreement. Because an unconditional fourth
  word is also the cheapest escape from REQ-13 (paste it everywhere, no row can
  disagree, the marker rule becomes a rule about the empty set — the Phase 2 rot
  shape), which five cells may use it is pinned literally in `UNREAD_POSITIONS`.
- **Files modified:** `README.md`, `tests/test_support_matrix.py`,
  `docs/retailer-evidence.md`
- **Verification:** `test_only_the_pinned_cells_say_unread` and
  `test_an_unread_cell_on_a_row_that_never_earned_one_fails_the_pin` (watched
  failing on Nintendo), plus
  `test_the_marker_is_unearned_on_a_row_whose_document_was_never_read`.
- **Committed in:** `a7d4543`

**3. [Rule 2 - Missing critical functionality] `_positionless` also requires the path in backticks**

- **Found during:** Task 3
- **Issue:** The plan specified the backticked path as part of the cell format but
  put only the opening word under the rule, so `permits` alone would have passed.
  `robots.txt` rules are per-path — Target permits `/p/` while `redsky.target.com`
  is `Disallow: /` for every agent — so a bare `permits` is true of one host and
  false of another in a cell claiming to describe the path fetched.
- **Fix:** A judged robots cell must contain a backtick. Watched failing via
  `test_a_robots_position_without_a_path_fails_the_position_rule`.
- **Committed in:** `a7d4543`

## Issues Encountered

**One politeness-budget slip, recorded rather than rounded off.** The rule is "on a
refusal, record it and move to the next *retailer*". The guard was written against
HTTP ≥ 400, and Best Buy refused at the transport layer with **no status code at
all**, so the guard did not fire and the Best Buy terms request went out after its
`robots.txt` request had already been refused. One request too many to a retailer
that had just said no. It was not a retry (a different document), the total stayed
under the cap at 7 of 8, and spacing held at 16 s — but the instruction was "move
on" and it did not. Written into `docs/retailer-evidence.md` as well as here.

**A GameStop control needed a retry.** The post-fetch `control_check.py` printed
`retrying gamestop/CONTROL — PS5 console: fetch failed: HTTP 403` before passing
4/4 — the first 403 this repo has recorded on a live control, minutes after plain
`curl` was refused 403 by `gamestop.com/robots.txt` from the same host. The retry
succeeded and the monitor is fine, so it is a near miss, not a failure. It is also
why no eighth request was spent going back to GameStop: a blocked IP costs Dan a
working monitor, and GameStop is one of the four retailers actually watched.

**Three of four policy documents could not be read, and escalation was refused.**
`boty.fetch.get` (curl_cffi) would very likely have read all of them — it reads
GameStop product pages every verify run. Re-requesting through the impersonating
transport after a plain-curl refusal is escalation, which the phase forbids, so
GameStop's and Best Buy's positions stay `unread`. That is a decision for a later
plan to take deliberately, not one to take by reflex inside this one.
