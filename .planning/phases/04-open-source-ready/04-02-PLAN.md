has a `## License` heading in `README.md:411-413` saying MIT — and ships no
licence text at all. `git ls-files | grep -ci licen` returns `0`. The GitHub API
reports `license: None`. A public project asserting a licence with no licence
text arguably grants nobody any rights.

That is not a missing file. It is the exact failure shape

<measured_facts>
Established first-hand during planning, on this box, against setuptools 83.0.0
(the version `pip`'s build isolation resolves today for `setuptools>=68`). Do
not re-derive these; do check them still hold if a command behaves oddly.

1. **`license = { text = "MIT" }` is deprecated and dated.** Preparing wheel
   metadata with the current `pyproject.toml` prints:
   `SetuptoolsDeprecationWarning: `project.license` as a TOML table is deprecated`
   … *"Please use a simple string containing a SPDX expression for
   `project.license`. You can also use `project.license-files`. (Both options
   available on setuptools>=77.0.0). By 2027-Feb-18, you need to update your
   project and remove deprecated calls or your builds will no longer be
   supported."* It still builds, and emits `Metadata-Version: 2.4` with a
   free-text `License: MIT` field.

2. **The PEP 639 form is clean.** `license = "MIT"` plus
   `license-files = ["LICENSE"]` emits `License-Expression: MIT` and
   `License-File: LICENSE`, places the file at
   `bot_y-0.1.0.dist-info/licenses/LICENSE`, and prints no warning at all.

3. **A `License ::` classifier alongside the SPDX expression is a hard build
   error**, not a warning:
   `setuptools.errors.InvalidConfigError: License classifiers have been
   superseded by license expressions (see PEP 639). Please remove: License ::
   OSI Approved :: MIT License`. So the classifier list must not contain one.

4. **setuptools does NOT enforce that a `license-files` target exists.** With
   `license-files = ["LICENSE"]` and no `LICENSE` on disk, the build succeeds
   silently, emits `License-Expression: MIT`, emits **no** `License-File`, and
   writes no `licenses/` directory. *The build is not the gate.* This is the
   single most important fact in this plan and it is why task 3 exists.

5. **`[tool.setuptools.packages.find] include = ["boty*"]` constrains the WHEEL,
   not the sdist.** Built from the tracked tree with no `MANIFEST.in`, the sdist
   contained `boty/*.py`, `README.md`, `pyproject.toml`, `PKG-INFO`, a generated
   `setup.cfg`, `bot_y.egg-info/*` — **and every `tests/test_*.py`**, while
   shipping neither `tests/conftest.py`, `tests/fixtures/`, `config/products.yaml`
   nor `scripts/`. That is a test suite that cannot run, published to PyPI.

6. **`prune` is silent, `exclude` is noisy.** `prune tests` removed `tests/`
   from the sdist. `prune` lines naming directories that were never included
   printed nothing. An `exclude` line naming a file that was never included
   printed `warning: no previously-included files found matching '…'` on every
   build. Use `prune`; do not add `exclude` lines for files that never enter.

7. **`tomllib` is Python 3.11+.** `requires-python = ">=3.10"` and
   `[tool.mypy] python_version = "3.10"` both claim 3.10, and 04-04 pins CI to
   3.10 precisely because testing the floor is what the config claims. So the
   test module in task 3 must not import `tomllib`. Acceptance commands run
   through `.venv/bin/python` (3.12 on this box) and may use it freely.
</measured_facts>
