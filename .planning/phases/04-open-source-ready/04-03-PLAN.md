<objective>
This repo has no linter. `grep -rin 'ruff|flake8|black|pylint'` across the source,
`pyproject.toml` and the `Makefile` returns zero hits, while REQ-10 says in its own
wording that CI runs "lint, type check and the offline test suite on every PR". The
type check and the suite exist and are wired into `make verify`. The lint half does
not exist at all.

So this plan introduces one, resolves what it finds, and wires it the way every other
check here is wired — into the `Makefile`, so `make verify`, a contributor's laptop and
04-04's CI run the identical thing with one definition of the rule set.

Three things make this more than `pip install ruff`:

1. **The rule selection is a decision, and it was measured.** Selecting `E` wholesale
   produces 497 findings, every one of them `E501` line-too-long, over the prose comment
   blocks that carry this project's recorded decisions — the AGPL `nodriver` audit, the
   mypy-strictness rationale, the `MARKETPLACES` absence-is-a-claim block. `ruff format`
   would reformat 32 of 36 files immediately before a 1.0.0 tag. Both are rejected in
   writing, in the config, in this repo's comment-as-decision-record idiom.
2. **The findings are resolved by hand where they touch a detector.** `ruff check --fix
   --unsafe-fixes` rewrites `boty/monitor.py`'s `zip(results, transitions)` to
   `strict=False` — freezing silent truncation in the list that produces restock alerts.
   That is measured, not hypothetical, and it is the exact silent-wrong-verdict failure
   this project exists to prevent.
3. **A stage added to `verify` gets watched failing.** `tests/test_verify_makefile.py`
   gains a `LINT_RC` stub branch and a test that forces `lint` red *inside* `verify`,
   copying the existing trap-per-stage pattern rather than improvising one. This project
   has already shipped a gate that was never watched failing; it does not ship a second.

Purpose: REQ-10's lint half, and the precondition for 04-04 — CI cannot lint before a
linter exists and its findings are resolved, and landing CI first would simply paint
`main` red.

Output: `ruff` in the `dev` extra, `[tool.ruff]` in `pyproject.toml`, a clean tree, a
`lint` target, a `lint` stage in `verify`, two new README stage rows, and two new tests.
</objective>

<measured_facts>
Established first-hand during planning on 2026-08-04, against **ruff 0.16.1** in a
throwaway venv, over the tree as it stands at commit `b0a272f` — that is, **before**
04-01 and 04-02 land their new files. Do not re-derive the reasoning; **do** re-measure
the counts, because wave 1 adds `tests/test_contributor_docs.py` and
`tests/test_packaging_metadata.py` ahead of this plan.

1. **The curated selection produces 20 findings**, 10 of them safe-autofixable and 9
   requiring `--unsafe-fixes`. The selection is
   `["F", "E4", "E7", "E9", "W", "I", "UP", "B", "SIM", "C4", "RUF"]` with
   `external = ["E402"]` and `allowed-confusables = ["–", "—"]`. `E4`/`E7`/`E9`/`F` is
   ruff's own default set — the split exists precisely because `E5` (line length) is
   contentious.

2. **`E` wholesale is a trap.** 497 findings, all of them `E501`. Measured separately:
   106 lines in `boty/`, `scripts/` and `tests/` exceed 100 characters and the longest
   is **473**. They are prose comment blocks and docstrings that quote measurements
   verbatim.

3. **`ruff format --check`: 32 files would be reformatted, 4 already formatted.**

4. **Ruff does not raise `E402` for module-level imports that follow a `sys.path`
   mutation.** Verified against a two-file probe: a plain out-of-order import is flagged;
   the same import after `sys.path.insert(...)` is not. flake8/pycodestyle flag both.
   Consequence: the seven `# noqa: E402` directives in `scripts/control_check.py` and
   `scripts/evidence_check.py` are inert under ruff, so `RUF100` calls all seven unused
   — and its fix is a **safe** `[*]` fix, so a blanket `ruff check --fix` deletes them.

5. **`external = ["E402"]` resolves that without weakening anything.** Measured both
   directions: with it set, `RUF100` leaves the seven directives alone, **and** a file
   containing a genuine `E402` is still reported. `external` changes what `RUF100`
   considers unused; it does not switch `E402` off.

6. **`allowed-confusables = ["–", "—"]` clears RUF001/RUF002 completely.** The three
   findings were EN DASHes inside docstrings and strings that quote measurements — e.g.
   `1.9–3.2 MB each` in `check_amazon`'s docstring, which records a live probe.

7. **`python -m ruff` works** and is the invocation this plan uses, not the `ruff`
   console script. Two reasons, both load-bearing: it runs under the interpreter
   `$(PYTHON)` names, and `tests/test_verify_makefile.py` stubs `$(PYTHON)` — a bare
   `ruff` would be unreachable from the stub, so the stage could never be watched
   failing.

8. **`ruff` has zero transitive dependencies.** `pip install ruff` into an empty venv
   yields exactly `pip` and `ruff`. PyPI metadata: `requires_dist: null`, licence MIT.

9. **Timing, on this box:** `ruff check --no-cache` over 35 files takes **0.02 s**;
   `mypy` 0.09 s; `identity_check.py --all` 3.33 s over 132 files. `lint` is the cheapest
   code check in the file, which is why it goes second — after `identity`, whose position
   is justified by consequence rather than cost ("a leak is the one failure you cannot
   walk back after a push").

10. **`include = ["boty/**/*.py", "scripts/**/*.py", "tests/**/*.py"]` makes a bare
    `ruff check` cover exactly 35 files** — the same three directories `make lint` names,
    and the same idiom as `[tool.mypy] files = ["boty", "scripts"]`: committed so a bare
    invocation checks the same thing for everyone.

11. **`target-version` is left unset on purpose.** Ruff infers it from
    `requires-python = ">=3.10"`; setting it would duplicate the floor in a second place
    where it can drift. Verified: the inferred run and an explicit `--target-version
    py310` run produce byte-identical output.

12. **The ruff cache self-ignores.** `.ruff_cache/` is created at the repo root and ruff
    writes `.ruff_cache/.gitignore` containing `*`, so `git status` stays clean and
    04-02's `_tracked_top_level_dirs()` does not see it. That is an implementation detail
    of ruff's, not a contract, which is why this plan adds the explicit `.gitignore` line
    anyway.

13. **`scripts/mutation_check.py` raises `HarnessError` when a mutation's `search` anchor
    is not found**, naming the mutation and the string it looked for. So an 8/8 result is
    itself the proof that no lint fix moved a load-bearing line; a drifted anchor cannot
    be mistaken for a survivor.
</measured_facts>

<scope_note>

**This plan is three tasks and 16 files, which is at the top of the range. It stays one
plan, and Task 3 is the sanctioned split point if it turns out not to.**

The size is real: ~20 hand-adjudicated findings across `boty/`, `scripts/` and `tests/`,
plus a new `verify` stage and two new tests, with Task 2 alone touching 11 files. It was
kept whole for one reason — the three tasks are one decision carried through. The rule
set chosen in Task 1 determines the findings resolved in Task 2, and the stage wired in
Task 3 is what makes both of them a gate rather than a one-off cleanup. Splitting them
across plans means the rule-set reasoning gets re-derived from a summary instead of read
from the config it was written into. The counterweight is that Task 2's risk is bounded
by measurement rather than by attention: every finding carries a written disposition
before execution starts, the load-bearing ones are hand-resolved with `grep` acceptance
criteria, and `scripts/mutation_check.py` at 8/8 is the check that catches a fix that
softened a detector. That is not context-sensitive in the way reading 11 files is.

Renumbering was rejected deliberately: `04-PLAN-OUTLINE.md`, `ROADMAP.md` and 04-04's
`depends_on` all name `04-03` as one plan, and a mid-phase renumber costs more than it
buys while the plan is still executable as written.

**The fallback, if context pressure shows during execution.** The split point is the
boundary between Task 2 and Task 3 — nowhere else.

- **Why there.** After Task 2 the tree is coherent and shippable: `ruff` is installed and
  pinned, the rule set is committed, the tree is lint-clean, `make verify-offline` is
  green and `mutation_check.py` is 8/8. Nothing is half-wired, because nothing has been
  wired yet.
- **Why not inside Task 3.** Its four parts are mutually load-bearing. A `lint` stage
  without the README row makes `test_the_documented_stages_are_the_stages_verify_runs`
  red; the README row without the stage makes it red from the other side; and the stage
  without `LINT_RC` is a gate that was never watched failing, which is the specific
  failure this plan exists to not repeat. Task 3 lands whole or not at all.
- **How to take it.** Stop after Task 2's verification passes. Write
  `04-03-SUMMARY.md` covering Tasks 1-2, and open it with an explicit **PARTIAL — Task 3
  outstanding** line naming what is missing: no `lint` target, no `lint` stage in
  `verify`, no README `lint`/`identity` rows, no `LINT_RC`. Then request `04-03b` for
  Task 3 as written here, wave 4, `depends_on: ["04-03"]`, files
  `Makefile, README.md, tests/test_verify_makefile.py`.
- **What the split costs, and who has to be told.** REQ-10's lint half is **not**
  satisfied by Tasks 1-2 alone — a linter that `make verify` does not run is a linter a
  contributor can skip. And 04-04 is written against the handoff note at the bottom of
  this plan: CI's entry point is `make verify-offline`, which is only true of lint once
  Task 3 lands. So a partial summary must say, in as many words, that **04-04 must not
  start until 04-03b is done**, or CI will claim to lint and not lint.

Do not take this fallback pre-emptively. It is the sanctioned improvisation-free exit if
context is genuinely short at the Task 2/Task 3 boundary, not a default.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| linter autofix → detector source | `ruff --fix` writes to `boty/` and `scripts/`. A fix that changes what a checker decides produces a wrong stock verdict, which is this project's core failure mode and the one thing a green test suite is least likely to notice |
| third-party build tool → contributor and CI machines | `ruff` executes on every contributor's laptop and, after 04-04, on GitHub's runners. It is a compiled binary shipped as a wheel |
| rule selection → the recorded prose | Comment blocks in this tree carry decisions cited as constraints from CONTEXT and PATTERNS — the AGPL `nodriver` audit, the mypy-strictness rationale, the `MARKETPLACES` absence-is-a-claim block, the redaction records. A rule that makes them non-compliant is a rule that pressures a contributor into rewriting them |
| new `verify` stage → the exit-code contract | Every phase of this project states its success criteria as "`make verify` exits 0". A stage whose failure does not reach that number silently devalues every criterion behind it |
