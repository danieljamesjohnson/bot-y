<objective>
Build rung 3 of the escalation ladder as a transport, prove offline that it cannot
leak into the test suite, and then answer the phase's single largest unknown:
**can a browser read a Best Buy product page at all?**

Nothing else in Phase 2 should be built on an assumption about that. Research is
disabled on this project, so `nodriver` is unvalidated and no browser adapter has
ever existed in this codebase (`02-PATTERNS.md` §"No Analog Found"). This plan
front-loads the answer so a failure lands in task 3 of plan 01, not task 9 of
plan 03.

Purpose: honour the locked decision that Best Buy's primary path is rung 3,
browser, credential-free (D-01), while honouring the equally locked decision that
a retailer we cannot reach is documented with evidence rather than faked (D-03).
Both outcomes of the spike are acceptable completions of this plan. Only a
fabricated one is not.

Output: `boty/browser.py`, a `browser` extra, an extended offline network guard,
offline tests, and `docs/retailer-evidence.md` carrying a real REACHABLE/REFUSED
verdict for Best Buy.

  the official API is an optional upgrade when `BESTBUY_API_KEY` is set.

- **D-03** — a retailer that cannot be reached is documented with evidence, never faked.

<design>
Contracts this plan creates. Later plans consume them by name — build these
exactly, so 02-03 does not have to go looking.

**`boty/browser.py`** — a new module, sibling to `boty/fetch.py`. It is a
*transport*, not a checker: it knows nothing about watches, offers or verdicts.

- `BROWSER_PATH_ENV = "BOTY_BROWSER_PATH"` — module constant.
- `find_browser() -> str | None` — returns `os.environ[BROWSER_PATH_ENV]` if set,
  else the first hit from `shutil.which` over `google-chrome`,
  `google-chrome-stable`, `chromium`, `chromium-browser`, `chrome`; else `None`.
  Deliberately reads the environment directly rather than going through
  `Config`: this is a property of the *host*, like a `PATH` lookup, not a
  per-monitor setting. No danserver-specific path is ever hardcoded — the repo
  must stay honest for a fresh clone.
- `_render(url: str, executable: str | None, timeout: float, settle_seconds: float) -> str`
  — the ONLY function in the codebase that calls `nodriver`. Imports `nodriver`
  *inside the function body* (lazy, per the `boty/fixtures.py:82` precedent), starts
  a headless browser, navigates, waits `settle_seconds` for client-side rendering,
  returns the rendered HTML, and stops the browser in a `finally` on every path.
  The whole async body is bounded by `asyncio.wait_for(..., timeout)` so a hung
  browser cannot wedge a monitor cycle. This function is the guard seam: it is
  module-level and patchable by name, mirroring
  `monkeypatch.setattr(retailers, "get", ...)` in `tests/test_retailers.py:33-46`.
- `fetch_rendered(url: str, *, timeout: float = 45.0, settle_seconds: float = 3.0) -> Page`
  — public entry point. Calls `find_browser()`, calls `_render`, scans the
  returned HTML for `boty.fetch.BLOCK_PHRASES` and raises `boty.fetch.Blocked`
  on a match, and returns `boty.fetch.Page(url=url, status=200, text=html)`.
  Converts `ImportError` into `FetchError` naming `pip install 'bot-y[browser]'`,
  a missing browser binary into `FetchError` naming `BOTY_BROWSER_PATH`, and any
  other `Exception` into `FetchError`. It must catch `Exception`, never
  `BaseException` — that is what lets the test guard escape, exactly as
  `boty/fetch.py:85` does today.

`Page.status` is set to `200` and that must be commented in the source: nodriver's
simple API does not surface the main frame's response status, so `200` here means
"the browser navigated", not "the server said OK". Block detection is by phrase
against the rendered DOM, which is the piece of `boty/fetch.py` that genuinely
transfers to a browser.

**`pyproject.toml`** — add a `browser = ["nodriver>=0.38"]` optional-dependency
extra alongside `dev`, with the same rationale comment `dev` carries: a deployed
monitor must not be forced to pull a browser driver onto the box. Add
`nodriver.*` to the existing `ignore_missing_imports` mypy override list —
`files = ["boty", "scripts"]` with `disallow_untyped_defs`, so `make types` will
fail on an untyped third-party import otherwise.

**`tests/conftest.py`** — the autouse `no_network` guard currently patches
`curl_cffi.requests.*` and three `socket` entry points. A browser drives Chrome
over a CDP websocket in a *subprocess* and would slip straight past all of them,
which would let a test suite silently launch a browser and hit bestbuy.com —
defeating Phase 1's entire offline guarantee. Extend the same fixture with
`boty.browser._render` (the primary seam) and
`asyncio.base_events.BaseEventLoop.create_connection` (belt and braces for the
CDP socket). Do **not** patch `subprocess.Popen`: `tests/test_verify_makefile.py`
and `tests/test_control_check.py` legitimately shell out, and blocking that would
break the suite for the wrong reason.
</design>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI → project venv | A new third-party package enters the dependency surface |
| retailer page → rendered DOM → our process | Attacker-controlled HTML and JavaScript is *executed*, not merely parsed — this is new for this codebase |
| browser subprocess → danserver host | A full Chrome process is spawned with filesystem and network access |
| rendered DOM → Result.detail → served/boty/status.json | Retailer-controlled text can reach a file served over HTTP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-SC | Tampering | `pip install nodriver` | mitigate | Task 1 is a blocking human legitimacy gate — PyPI project page, upstream repo match, release history, typosquat check. Never auto-approved. |
| T-02-01 | Elevation of Privilege | `boty/browser.py` executing retailer JavaScript | mitigate | Headless, no extensions, no persistent profile, no credentials ever passed to the browser. The browser sees only public product URLs; `~/.config/boty/env` is never read by this module. |
| T-02-02 | Denial of Service | `_render` hanging on a slow or hostile page | mitigate | Whole coroutine bounded by `asyncio.wait_for(..., timeout)` (default 45s) and `browser.stop()` in a `finally` on every path, so a wedged browser cannot stall the monitor cycle or leak Chrome processes. |
| T-02-03 | Spoofing | A challenge page rendered as if it were a product page | mitigate | `boty.fetch.BLOCK_PHRASES` scanned against the rendered DOM; a match raises `Blocked`, which callers turn into UNKNOWN, never a stock verdict. |
| T-02-04 | Information Disclosure | Test suite silently launching a browser against live retailers | mitigate | `no_network` extended to patch `boty.browser._render` and `BaseEventLoop.create_connection`; a self-test in `tests/test_browser.py` proves the guard fires and is not downgraded. |
| T-02-05 | Repudiation | A "we tried and failed" claim with no evidence | mitigate | `docs/retailer-evidence.md` records the concrete observation (phrase matched, bytes, binary used) rather than a conclusion. |
| T-02-06 | Information Disclosure | Hardcoding `/home/dan/.cache/ms-playwright/...` into a public repo | accept→mitigate | Path stays out of committed source entirely; resolved at run time from `BOTY_BROWSER_PATH` or `shutil.which`. |
</threat_model>
