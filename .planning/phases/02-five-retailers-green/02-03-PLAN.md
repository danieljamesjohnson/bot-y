<design>
**The dispatch seam is `boty/cli.py:_make_checker` and nowhere else.**
`scripts/control_check.py:152` deliberately builds its checker with the same
function, because a control check that routed requests differently from the
running monitor would prove something about a code path nobody runs. Extend that
one function; do not invent a registry. The decided behaviour is a third arm of
the same `if`: for `bestbuy`, use `check_bestbuy_api` when `cfg.bestbuy_api_key`
is truthy, otherwise `check_bestbuy_browser`.

**`watch.target` for `bestbuy` stays the SKU, not a URL.** `check_bestbuy_api`
already treats it that way and derives the public product URL from it. Both paths
must accept the same YAML entry, so extract that construction into a module
function named `bestbuy_product_url(sku: str) -> str` and call it from both. Its
template is whichever form the spike proved works; `boty/retailers.py:158` assumes
`https://www.bestbuy.com/site/-/{sku}.p` and `tests/test_retailers.py:350` asserts
that exact string, so if the spike found a different working form, that assertion
moves with it.

**Refactor `check_html` into fetch + verdict, minimally.** `check_bestbuy_browser`
must not reimplement the UNKNOWN logic — the WR-02 and WR-03 escape hatches
(`boty/retailers.py:90-118`) are this phase's most important behaviour and they
belong in exactly one place. Split the body:

- `_verdict_from_html(watch, html, *, url, first_party_only, rung) -> Result` —
  everything from `parse.ldjson_offers` downward, with `url=url` and `rung=rung`
  on every `Result` it returns.
- `check_html(watch, *, first_party_only=True)` — signature and behaviour
  unchanged: fetch with the module-level `get`, catch `Blocked` and `FetchError`,
  then delegate with `url=watch.target, rung=Rung.TLS`.
- `check_bestbuy_browser(watch, *, first_party_only=True)` — compute
  `product_url = bestbuy_product_url(watch.target)`, fetch it via
  `fetch_rendered` imported at module scope into `retailers` (so a test can do
  `monkeypatch.setattr(retailers, "fetch_rendered", ...)` in exactly the shape
  `_serve` already uses for `get`), catch `Blocked` / `FetchError` into UNKNOWN
  with a reason, then delegate with `url=product_url, rung=Rung.BROWSER`.

`rung=Rung.API` on `check_bestbuy_api` is **not** this plan's work — 02-02 owns
the `Rung` enum and adds it there, deliberately, so it cannot be lost inside a
branch this plan might skip. Confirm it is present rather than re-adding it.

**Mutation anchors are exact source substrings — this refactor can break them.**
`scripts/mutation_check.py` M2 anchors on the literal text
`Availability.UNKNOWN,` followed by a newline, twelve spaces, and
`detail="no structured stock data found`. M3 anchors on `if first_party_only:`
inside `_pick`. `apply_mutation` raises a HARNESS ERROR when an anchor drifts,
which takes `make verify` down for a reason that looks nothing like its cause.
So: the "no structured stock data found" return must land inside
`_verdict_from_html` at the same nesting depth it has today, and `_pick` must not
be touched at all. Run `make mutation` immediately after the refactor and before
writing any new tests.

**Price is not optional.** `Result.alertable` returns False when a ceiling is
configured and `price is None` (`boty/models.py:73-75`, the WR-01 hardening). An
adapter that reads availability and skips price can never alert on the GO Plus +
watch, which is the entire reason the retailer is being added. If the spike found
the rendered page carries no usable schema.org price, add a *named* Best Buy
extractor to `boty/parse.py` following the `nextdata_offers` convention — an
explicit dotted path constant plus a `_dig` walk, never a generic search, because
a product page also embeds recommendations and accessories with their own
availability and a generic walk happily reports a screen protector as your
restock. Do not generalise `nextdata_offers`; `tests/test_parse.py:124-135` pins
its one-offer-only behaviour as a regression. Every extractor returns
`list[Offer] | None` with the three-valued contract intact: `None` means "no
structured data of this kind here", `[]` means "a product with no offers".

**Seller attribution decides whether a Best Buy control can ever go green.**
`bestbuy` is in `MARKETPLACES` (`boty/retailers.py:39`), so `_pick` refuses an
offer with `seller is None` and the verdict becomes UNKNOWN. Use the spike's
finding:
  - If the page attributes a seller, read it into `Offer.seller` and everything
    works unchanged.
  - If it does not, and the spike established that Best Buy US product pages do
    surface third-party sellers, the adapter must read the DOM's "Sold by"
    attribution — that is the honest fix.
  - Removing `bestbuy` from `MARKETPLACES` re-opens WR-02 for that retailer and
    is acceptable only with recorded evidence that third-party sellers do not
    appear on its product pages. If you take that route, put the evidence in
    `docs/retailer-evidence.md` and add a test pinning the new behaviour.

**Control selection.** `config/products.yaml:49-51` states the rule: first-party,
restocked routinely, never subject to a marketplace buy-box fight, and explicitly
not a console. Name it `CONTROL — <product>` and give it **no `max_price`** — a
ceiling on a control is meaningless and `test_gamestop_control_is_in_stock_and_alertable`
depends on its absence.

**Fixtures need a browser, and the flag is not Best Buy's alone.**
`boty capture-fixture` goes through `fetch.get`, which Best Buy refuses at the
connection layer, so it cannot capture a Best Buy page today. 02-01 already added
the `browser: bool = False` parameter to `boty/fixtures.py:capture`, selecting
`boty.browser.fetch_rendered` instead of `fetch.get` with the same lazy import, so
importing `boty.fixtures` still cannot reach the network, and `Blocked` /
`FetchError` still propagate — a capture that swallowed them would write a
challenge page to disk under a product's name and poison every test that reads it.

What remains here is the matching `--browser` argparse flag in `boty/cli.py`, and
it is added **under both branches** (task 1, step 1) because 02-04's ladder for
Pokémon Center and Nintendo needs it regardless of what Best Buy did.
</design>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `BESTBUY_API_KEY` → request URL → Result → `served/boty/status.json` → HTTP | A mode-600 credential can reach a file served over the network |
| bestbuy.com HTML (rendered) → parser → verdict | Attacker-controlled markup decides a stock claim |
| browser subprocess → danserver host | A full Chrome process is spawned per Best Buy check |
| `config/products.yaml` → `_make_checker` → `control_check.py` | One dispatch decision governs both the monitor and the gate that judges it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Information Disclosure | `check_bestbuy_api` credential leak (CR-03 class) | mitigate | `bestbuy_product_url` is computed up front and used as `Result.url` on every return path; exception-derived text goes through `_redact`. `test_bestbuy_api_key_never_reaches_the_result` is parameterised over four error paths and must keep passing after the `Rung.API` change. |
| T-02-12 | Spoofing | A Best Buy challenge page parsed as a product page | mitigate | `fetch_rendered` scans the rendered DOM for `BLOCK_PHRASES` and raises `Blocked`; `check_bestbuy_browser` converts that to UNKNOWN with "blocked" in the detail. Tested. |
| T-02-13 | Tampering | A marketplace offer alerting as a restock | mitigate | `bestbuy` stays in `MARKETPLACES` unless the spike produced evidence otherwise; `_pick` is not modified; the price ceiling remains an independent second defence. |
| T-02-14 | Repudiation | The refactor silently disabling the mutation gate | mitigate | M2's anchor indentation is preserved by construction and `make mutation` is run inside task 1's `<verify>`, before any new tests exist to mask a regression. |
| T-02-15 | Denial of Service | Browser processes accumulating across monitor cycles | mitigate | `boty/browser.py` bounds each render with a timeout and stops the browser in a `finally`; the live control stage of `make verify` exercises that path for real. |
| T-02-16 | Elevation of Privilege | A fixture capture writing a challenge page to disk | mitigate | `capture()` lets `Blocked`/`FetchError` propagate; `boty/cli.py:_capture_fixture` already refuses to save and says why. The `--browser` flag must not add a swallowing handler. |
| T-02-SC | Tampering | package-manager installs | mitigate | This plan installs nothing new; `nodriver` was gated by the blocking human checkpoint in 02-01. |
