<objective>
Close the phase: register the mutation that would notice if the lockstep came back, establish
criterion 4's budget half without running the thing that would spend it, read the gate's verdict line
rather than its exit code, and write a verdict table that rounds nothing up.

**Purpose.** Four of this phase's five criteria are about the schedule and are discharged by the time
this plan starts. Two things are left, and both are the kind this repository takes seriously.

**Criterion 5 asks for a mutation observed CAUGHT.** A gate nobody has watched fail is not a gate,
and a mutation anchored on prose is a gate that tests the prose. M43 must rebuild the **lockstep
itself** — a line whose removal changes *when a request is made* — so that a future refactor which
preserves the de-lockstep and rewrites every word around it leaves it still caught. And it must be
honest about what it buys: M42 was registered in Phase 8, measured to have a kill set that is a
proper subset of M33's, and that was **recorded as a finding rather than rounded up into coverage**.
The same measurement is owed here.

**Criterion 4's budget half is the one this phase expects to land at MET IN PART**, and
`09-DECISIONS.md` § *Collision 8* said so before any measurement was taken rather than after one
disappointed. `boty check` makes live retailer requests and writes the document the daemon owns; this
phase makes no live request. So the budget is **bounded from evidence that already exists** — the
structural fact that the check path's pacer is never handed to `run_once`, so no scheduling change in
this phase can reach it, plus the last published whole-pass duration. That is a bound and not a
re-measurement, and criterion 4 asks for a re-measurement, so the verdict says **MET IN PART** and
names which half is missing.

**Output.** M43 caught and honestly priced, a budget statement recorded beside the existing REQ-08
evidence, a green `make verify-offline` whose verdict line is quoted, and a five-criterion table.

## The five criteria this phase is judged on (verbatim from ROADMAP.md, unedited)

  1. Two retailers whose intervals coincide are **not** dispatched inside the same short window; the bound is a stated number of seconds and is asserted on the schedule, never on a wall clock
  2. Each retailer's next-attempt time is **independent**: changing one retailer's interval or backoff moves that retailer's schedule and no other's, asserted in both directions
  3. Over a simulated day, the maximum number of retailers requested within any 60-second window is a **stated number**, and it is smaller than the current six
  4. **No regression in what already works**: per-retailer cadence and backoff still hold, and `boty check` — a deliberate full pass, which is a different thing from the daemon's schedule — still completes inside REQ-08's 2-minute budget, re-measured rather than assumed
  5. `make verify-offline` exits 0, with at least one new mutation registered and observed CAUGHT
</objective>
