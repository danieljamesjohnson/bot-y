<decision>

## The gate is scoped to `CHANGELOG.md`, and the scope is proved rather than asserted

`CHANGELOG.md` is the file the criterion names, the file `MANIFEST.in` puts in the sdist, and the
file `pyproject.toml` points every installer at. Two independent arguments for not widening it, and
the second is the stronger one:

- **Measured (F4):** every occurrence in the tracked tree is a deliberate quotation of the defect
  inside `.planning/`, and `06-PATTERNS.md` became three of them in the act of measuring the sweep.
- **Structural (F4):** `tests/test_changelog.py` must contain the shapes it forbids. A tree-wide
  rule reddens its own definition, always, by construction.

Widening later is a decision with an `identity_check._PROBE_FILES` / `_PROBE_DIR_PREFIXES`-style
exemption attached, not a default. Name that mechanism in the docstring so a future widening starts
from the right place.

## Absence rules alone are worthless. Every prohibition is paired with a presence rule

This is `_extraction_mismatch`'s *"One-directional would be worthless"* applied to a document
instead of a table, and it is the trap this rule set walks straight into if nobody says so: **no
markup, no placeholders, ends with a newline — an empty file passes all three.** So does a file
gutted to its preamble. A gate that a deletion satisfies is not a gate.

So the set carries presence rules — at least one released heading, `## [Unreleased]` present, every
released section carrying a body — and **Task 2 watches the whole set biting on a document with no
release in it at all.**

## The red-watch is the incident, not an impression of it

`2ac965f^` still holds the document that shipped (F1). The corruption is not typed out; it is
recovered from git at execution, embedded as `HISTORICAL_TAIL` with the commit named, and appended
to the real shipped file. Every other corruption is derived from the real file the same way, in
`test_contributor_docs.py`'s `_corrupt` idiom.

**And the criterion is executed literally, once, on disk** (Task 3): that exact document restored
to `CHANGELOG.md`, the real suite run, the real red observed, the file restored with
`git checkout --`. Task 1 measures the *same* file and the *same* command returning **green**
before the gate exists. Green before, red after, same bytes, same command.

Unlike 06-03, no separate removal gate is needed: **the gate under construction is the removal
gate.** Commit the corrupted file and `make verify-offline` fails naming it.

## The pairing — the criterion is not met by a skip line

Every file-reading test carries `needs_changelog` and skips inside the mutation sandbox (F5). If
that were all, `make mutation` would print a skip line and the CHANGELOG gate would be inert in one
of the two places this suite runs — the exact defect `test_packaging_metadata.py` refused for
`MANIFEST.in`.

So the file is written in two halves:

- **The shipped-tree half** — every rule against the real `CHANGELOG.md`, and every rule against a
  corruption derived from it. Skips where the file is absent.
- **The unconditional half** — the same rule functions against `MINIMAL`, a small well-formed
  changelog defined in the module (deliberately carrying an inline-code angle-bracket token, so it
  proves F3's precision too), against corruptions of `MINIMAL`, against the empty document, and
  against `HISTORICAL_TAIL`. **No file read, so it runs in every sandbox.**

**And the pairing is pinned, not promised.** A test `ast`-walks this module, collects the test
functions carrying no skip decorator, and asserts every rule function is named by at least one of
them. Add a rule, forget its unconditional exercise, and that test goes red. Rule functions are
discovered from the module rather than from a hand-maintained tuple, so a new rule cannot escape
the way 06-03's F4 records a rule escaping `RULES`.

## No mutation. M23-M24 stay unallocated, and that is a finding

Four measured reasons:

1. **The harness mutates `boty/`.** Its own docstring says so — *"break the code on purpose"* — and
   all 16 idents target a file under `boty/` (F8). This plan writes no production code; its
   deliverable **is** a gate over a data file. There is nothing in `boty/` for it to break.
2. **The subject is out of the harness's reach.** `apply_mutation` string-replaces inside a file
   the sandbox copied, and `CHANGELOG.md` is not copied (F5).
3. **Making it reachable is self-justifying and lands in another plan's file.** Adding
   `CHANGELOG.md` to `SANDBOX_CONTENTS` so a mutation could exist would create an entry provable
   load-bearing only by the mutation that motivated it — failing Phase 4's recorded rule for that
   constant — and would put this plan into `scripts/mutation_check.py`, which is 06-01's and
   06-02's.
4. **What a mutation would have proved is proved better here.** The question a mutation answers is
   *does this gate actually bite where the suite runs?* Task 3 answers it directly by building a
   **real** `build_sandbox()` and observing which tests skip and which pass inside it — a count, not
   an inference.

Record the deliberate **M21-M24 gap** in the SUMMARY so 06-05 keeps M25-M26 and 06-06 does not read
four lost mutations. A mutation that *survives* is never explained away; a mutation that cannot
exist is recorded as not existing.

## Scope fence

The workflow half of REQ-19 is **06-03's** and landed in wave 3. The version roll, the
`pyproject.toml` ↔ `CHANGELOG.md` binding and the STATE.md binding are **06-05's**. This plan opens
**one file**, `tests/test_changelog.py`, and creates it. `CHANGELOG.md` is written to disk exactly
once, transiently, in Task 3, and restored byte-for-byte with `git checkout --` inside a `finally`;
it is **not** in `files_modified` and `git status --porcelain` must be clean afterwards.

`scripts/release_check.py` is **not touched.** It needs the network and is deliberately outside
`make verify`, so a contents rule there would never run in `verify-offline`, which is this phase's
gate. That is a finding, not a preference.

## Prohibited in this plan

No "v1", no "start with the markup rule and add the rest later" — an absence-only rule set is
satisfied by an empty file and shipping one would be this milestone's own defect. No spell-check, no
line-length rule, no prose-style rule: the gate is about what a stranger reads being *true and
whole*, not about how it is written. No network. No widening of `SANDBOX_CONTENTS`. **No rule may be
softened to get the shipped file green** — if a rule is red on arrival, the rule is wrong or the
CHANGELOG is wrong, and F3 says which is far more likely; fix the rule, never the assertion, and
never `CHANGELOG.md`.

If anything below cannot be built as written, stop and say so rather than shipping a narrower rule
that reads like the wide one.

The green side, the red side and the sandbox observation have different failure modes and different
evidence, and the third produces the record the criterion is actually judged on — the same reason
06-03 gave. All three touch one file plus one transient restore of a file already in this repo's
history.
