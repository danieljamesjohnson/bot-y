### F3 — Static beats dynamic here, and the cost is written down rather than hidden

`06-PATTERNS.md` left static-vs-dynamic open. Measured, it is not close:

- A **dynamic** binding must drive five adapters across three transports, including
  `check_bestbuy_api`, for which **no fixture exists** (`tests/fixtures/bestbuy/` holds two HTML
  files and no API payload), and two browser adapters needing a nodriver stub.
- A dynamic binding **still cannot see the routing `if`-chain**, which is half of the claim: a
  binding to `check_amazon` alone stays green if `_make_checker` stops routing amazon to it. M20
  exists to prove that half is load-bearing.
- `ast`-over-repo is an established idiom here: `tests/test_ci_workflow.py` walks its own source,
  and `tests/test_alert_text.py` — 05-02's prose-absence gate — walks `boty/monitor.py` and
  `boty/notify.py`. The precedent for AST over `boty/` from `tests/` already exists.

**The cost, stated rather than buried: a static gate asserts what the source says, not what runs.**
That cost is small here because the failure mode the criterion names *is a source edit* — a
developer changes an adapter's rung and forgets the README. And the runtime half is already
covered: `tests/test_retailers.py` asserts `result.rung is Rung.BROWSER` / `Rung.API` through
`_make_checker` for Best Buy on both arms. This gate binds the README to the source; those tests
bind the source to behaviour. Neither substitutes for the other, and the module docstring says so.

### F4 — Only a LITERAL `rung=Rung.X` keyword counts as a rung claim

`_verdict_from_html` takes `rung` as a *parameter* and passes `rung=rung` into `Result(...)`. That
is `ast.Name`, not `ast.Attribute`, so the walk does not see it and `_verdict_from_html` does not
appear in the rung map at all. **That is correct and deliberate** — a pass-through is not a claim
about which rung anything takes; the claim is made at the call site that supplies the literal.

The hole this leaves must be *reported*, not silently tolerated: an adapter reachable from routing
that carries no literal `rung=Rung.X` anywhere is a retailer whose rung the gate cannot read. Today
there are none — all five adapters carry at least one. A rule that returned an empty tuple for such
an adapter would let it masquerade as "no adapter", which is exactly what a rung-4 row wants to see.
So the two cases are distinguished in the finding.

### F5 — The mutation anchor, and why the obvious one mutates the wrong three retailers

`apply_mutation` does `before.replace(mutation.search, mutation.replace, 1)` — **first occurrence
wins**. Counted on the pre-06-01 tree:

| candidate `search` | occurrences | where |
|---|---|---|
| `rung=Rung.TLS,` | **2** | `check_html` first, then `check_amazon` |
| `        rung=Rung.TLS,\n    )` | 1 | `check_html` only |
| `        rung=Rung.TLS,\n        #` | **1** | `check_amazon` only |

So `06-PATTERNS.md`'s proposed bare anchor mutates `check_html` — which serves **GameStop, Walmart
and Nintendo** — and its `breaks=` sentence would describe something that did not happen.

**The disambiguator is the shortest extension of the naive anchor that is unique: the newline and
the indented `#` that opens `check_amazon`'s `sku=` comment.** It is one punctuation character of
comment, not comment prose, so rewording that comment does not break the anchor; deleting it
outright raises `HarnessError`, which is the harness refusing to run rather than checking less.

Verified by applying it to the real source: after the edit, `check_amazon` reads `('3',)` and
**`check_html` still reads `('1',)`**. That AST check — not the string count — is the proof that the
right adapter moved, and Task 3 makes it a permanent test rather than a one-time observation.

### F6 — M20's anchor, and that both adapters take the same call signature

`return check_target_browser(watch, first_party_only=cfg.first_party_only)` occurs **once** in

### F7 — Best Buy's conditional cell, decided here rather than discovered

`| Best Buy | 3 (2 with a key) | ... |` is a conditional rung and the routing chain agrees with it
exactly: the `bestbuy` arm returns `check_bestbuy_api` when `cfg.bestbuy_api_key` is set and
`check_bestbuy_browser` otherwise, giving `('2', '3')` against a declared `('2', '3')`.

So it needs **no special case** — it falls out of a set comparison. `_declared_rungs` reads the
established `rung[:1]` for the primary and every parenthesised digit as an alternate, and the rule
asserts **set equality**. That is two-directional by construction: an adapter taking a rung the cell
does not name goes red, and a cell naming a rung no adapter takes goes red. Dropping ` (2 with a
key)` while `check_bestbuy_api` still exists is a red-watch in Task 2.

## Static AST, both joins, argued in the module docstring

Settled here on F3, and the argument goes **into the file** rather than living only in this plan —
this codebase's dominant convention, and `06-CONTEXT.md` puts *"how the Rung binding is expressed"*
inside Claude's Discretion.

## The mapping is a pin, and it lives in the test file

`RUNG_NUMERALS` does not exist anywhere in this tree (§ *Finding 5* of the outline, re-confirmed).
It goes in `tests/test_support_matrix.py`, **not** in `boty/models.py`:

- A numeral is a documentation fact about the ladder `README.md` publishes, not a runtime fact.
  `models.py` deliberately keeps `Rung` out of `monitor` and `Health`, and its own docstring records
  that there is **no member for rung 4** because "a dropped retailer produces no readings".
- Putting it in `boty/` would put this plan into 06-01's files for no gain.

It is a **pin, not a rule**, in `UNREAD_POSITIONS`' and `TRUSTED_ACTION_OWNERS`' sense: enumerated
with its justification inline, so widening it means editing a red test. The justification is
quotable from both sides and they already agree word for word — README's ladder paragraph
(*"Rung 1 is impersonated HTTP, rung 2 a retailer's own sanctioned API, rung 3 a real browser, rung
4 'dropped, with the evidence written down'"*) and the three `Rung` member docstrings.

## Two directions, or it is worthless

`_extraction_mismatch`'s docstring says so in as many words and the same reasoning transfers
verbatim:

- **A working-rung row** (`rung[:1] in WORKING_RUNGS`): the numerals its cell declares must **equal**
  the numerals its adapters take. Not "include" — equality, so an unnamed second rung is caught too
  (F7).
- **A non-working-rung row** (`4`, or the `—` `UNPROBED_RUNG`): its retailer must have **no adapter
  binding at all**. Pokemon Center is the live case and it is clean today — absent from
  `KNOWN_RETAILERS`, no routing arm, no adapter.

A one-directional version would be satisfied by deleting adapters, or by writing `4` in every row.

## The gate may not pass vacuously

A static gate that cannot parse what it is looking at must **raise**, not return an empty mapping.
`_matrix` already sets that precedent in this same file (`assert start is not None, ...` with a
message saying what moved). `_routing` follows it: no `_make_checker`, no `check` closure, no
fallthrough `return` ⇒ `AssertionError` naming what was not found. Watched, in Task 2.
