**Purpose.** REQ-21's opening measurement was not that Walmart's last reading was old. It was that

**Output.** `State.read_at`; a `load` that accepts both shapes of the document and validates every

## The five criteria this phase is judged on (verbatim from ROADMAP.md, unedited)

  1. Every `Result` records when it was read, and that time is published per watch in `status.json`
  2. A reading with no recorded time is shown as UNKNOWN age, never as current — watched going red
  3. A reading older than its retailer's current interval is presented as stale in `status.json`, `boty check` and the dashboard, and the staleness is derived from the retailer's own pacing rather than a fixed clock
  4. The age survives a service restart, so a restart cannot make a two-day-old reading look fresh
  5. `make verify-offline` exits 0, and every gate this phase adds has been watched going red

**This plan owns criterion 4 whole.** It also carries the persistence half of criterion 2 — a
document that never recorded a moment loads as UNKNOWN, never as `now`. Criterion 5 binds here as
the red-watch on M32.

The shape it becomes, per entry:

```json
{
```

## AND ONE OF THOSE 13 ENTRIES IS A FOSSIL, WHICH THIS PLAN MUST NOT PAPER OVER

```
"walmart:Pokémon GO Plus +"   ->   "out_of_stock"
```

**That string can no longer be updated by anything.** The 2026-08-12 restart deployed Phase 5's
store-gap guard; `WALMART_STORE_ID` is still unset (`QUESTIONS.md` § 0f, open); so every Walmart
reading is now `Availability.UNKNOWN`; and `transitioned_to_stock` returns on UNKNOWN **before** it
writes. The value is not merely undated — it is **frozen**, and it will say `out_of_stock` until a
store is pinned.

So the design has one hard requirement beyond the migration: **a frozen reading must not come out
of this looking freshly persisted.** After this plan that row writes `"read_at": null` on every
cycle, for as long as it stays frozen, which is the honest output and is 07-06's checkpoint
material. Any design in which `save` supplies a stamp for an entry that has none would date the
fossil at the moment of every write — `pacing.py:196-199`'s recorded trap, verbatim:

> *"stamping at write time would refresh the record forever and the age-out would never fire once —
> a bound that cannot bind is worse than no bound, because it reads like one in the file."*

**`save` therefore never reads the clock. There is no `time.time()` in it.** That is a property a
test can assert, and Task 3 asserts it.

## THE GUARD THAT CLOSES HALF THE TRAP ALREADY EXISTS, AND IS INHERITED RATHER THAN REBUILT

`monitor.State.transitioned_to_stock` returns on UNKNOWN **before** it writes:

```python
        if result.availability is Availability.UNKNOWN:
            return False
        key = result.watch.key
        previous = self.seen.get(key)
        self.seen[key] = result.availability.value
```

So the persisted document is already written only when a verdict was resolved. **The stamp goes on
the line beside `self.seen[key] = …` and inherits exactly that rule.** No second guard is added:
`mutation_check.py:678`'s own warning is that *two gates on one rule means neither can be shown to
bite*.

## The version question, decided in writing rather than defaulted

`pacing.py` has the `STATE_VERSION` precedent and records what a bump costs (*"A v1 file is treated
as absent"*). **This document takes no version**, on three measured grounds, all of which land in
the code rather than only here:

1. **The new field's units cannot drift** the way a count's can. `STATE_VERSION` exists because
   `refusals` is a COUNT whose units are a policy decision — `BACKOFF_FACTOR` and the cap. Epoch
   seconds have no policy constant to be re-pointed against. That is the exact distinction
   `pacing.py:99-104` already draws; only the example on the other side of it has changed.
2. **The price of a version here is paid in alerts.** A file carrying the wrong version is *treated
   as absent*. Applied to `state.json` that discards every remembered availability, so the next
   IN_STOCK reading on each of the 13 watches reads as a fresh restock. Per-entry shape tolerance
   costs nothing and keeps the memory.
3. **A version does not answer the hazard that is actually there, which is a DOWNGRADE.** An older
   binary reading the newer document compares a mapping against `"in_stock"`, finds them unequal,
   and re-alerts. It would not read a version field either — the code that would check it is the
   code that does not exist yet. **That residual is priced in the code, not described:** measured
   against today's document, 8 of 13 entries are `in_stock`, 6 of those are controls and controls
   never alert, so the downgrade costs **at most two duplicate restock pushes** (the two GameStop
   `TRANSITION —` watches, which `config/products.yaml:330` records as deliberately not controls).
   And it is not one-way: an old binary rewrites the file mixed, and per-entry tolerance reads a
   mixed document without loss in either direction — which a version field could not do.

A **second document** is rejected on `pacing.py:277-297`'s own recorded argument: *"a second
gitignore line, a second corrupt-file path, and a second way for a restart to come back holding a
contradiction."*
