# Milestone v1.0.0 — Audit

**Status: `gaps_found`** — and the gap that matters is not a defect in the code.

## The headline

**v1.0.0 does not satisfy its own definition of done, because Dan has not bought a
Pokémon GO Plus +.** REQUIREMENTS.md says that outright and says why: *"The second is
not a joke requirement. The tool exists to solve one concrete problem, and a monitor
that runs beautifully while the thing stays unbought has not worked."*

Every GO Plus + watch reads `out_of_stock` — GameStop, Walmart, Nintendo, Amazon.
Best Buy and Target do not carry the product. Amazon's only listing is a $219 used unit
from a reseller, which both the seller filter and the price ceiling correctly suppress.
Four real listings watched; none has come back in stock.

That is a market condition, not a wiring failure. The integration checker traced the
whole restock chain — parse → state → edge detection → Apprise — to call sites and red
tests rather than accepting that it exists. It fires when the market changes. The
drought is real.

## What the audit actually found in the code

**0 blockers. 2 warnings.** Every cross-phase connection was proved by mutation or by a
call site, not by inspection:

- Config → adapter routing, the gate using the *same* router as the monitor (not a
  parallel registry), all six retailers with control watches, the `Extraction` axis
  threaded end to end from `models.py` through the CLI tags to `status.json` to the
  dashboard, the 3-member `Availability` invariant surviving 3.1's new axis, and Phase
  4's new config guard sitting *after* the fixture-capture early return so no Phase 1–3
  path regressed.
- `make verify-offline` exits 0: 531 passed, mypy clean over 18 files, 8/8 mutations
  caught, identity check PASS over 160 files.

The two warnings are in the frontmatter above. The sharper one is **REQ-13's Rung cell
is not bound to code** — a matrix row can lie about the escalation rung and no test goes
red, proved by mutating `check_amazon` to return `Rung.BROWSER` against a README that
says `1` and watching 131 tests stay green.

## What this milestone got right, which is most of it

Five phases, one of which (3.1) exists to reverse another after a decision was overruled
— and Phase 3's evidence was kept and marked historical rather than edited. Requirements
were repeatedly *refused* rather than claimed: REQ-07 left Pending by two plans that
half-satisfied it, REQ-11 flipped green twice by executors and reverted twice by the
orchestrator, criterion 1 of Phase 3.1 and criteria 3/5 of Phase 4 recorded UNMET rather
than reworded to pass. That is the project's core value applied to its own bookkeeping.

## Recommendation

Do not tag v1.0.0 as shipped. Its definition of done is honest and unmet, and the
withdrawn PyPI release means there is no external artifact whose version number needs
settling. The accurate record is: **the monitor is built, verified and running; the
purchase it exists to enable has not happened.**

The next milestone's subject — finding the product on eBay at a low price — is aimed at
exactly the unmet item.
