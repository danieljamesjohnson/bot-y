# Milestone v0.2 — Say Only What You Measured — Audit

**Status: `gaps_found`** — for one reason, and it is the milestone's own defect
wearing the milestone's own name.

## The headline

**Everything v0.2 built is in the tree. None of it is running.**

That is not a discovery — this project already says it, loudly, in five places. What
this audit adds is that it re-measured it rather than repeating it, at 10:28 on
2026-08-11, against the file the daemon had just written:

```
$ systemctl show boty.service -p MainPID -p ActiveEnterTimestamp
MainPID=3059142
ActiveEnterTimestamp=Tue 2026-08-04 17:48:52 CDT

$ python3 -c "print(sorted(json.load(open('served/boty/status.json'))['watches'][0].keys()))"
['alertable','availability','control','degraded','detail','extraction',
 'name','price','retailer','rung','url']              # no 'store'

$ grep -c 'probably broken' served/boty/status.json
1

$ find / -name pacer-state.json          # only pytest tmpdirs
```

So the thing actually watching for restocks publishes a verdict about a Walmart store
nobody chose (`out_of_stock` on the GO Plus + watch), tells a person the detector is
*probably broken* when nothing established that, and holds Amazon's fourteen refusals
in memory where a restart would erase them. Those are REQ-14, REQ-15 and REQ-16 —
the three requirements Phase 5 exists to close — described in the present tense.

**One new fact, which nobody had written down.** The gap is one command wide. `boty`
is an **editable install**: the `.pth` points at the working tree, `boty.__file__`
resolves to `/home/dan/CodeProjects/pokemongoplusplus/boty/__init__.py`, and the unit
runs that same tree's venv from that same directory. The new code is already sitting
on the deployed path. MainPID 3059142 is running 2026-08-04 bytes **in memory**
against 2026-08-11 source. `sudo systemctl restart boty` deploys REQ-15, REQ-16 and
REQ-17 whole, today, with no pin and no other prerequisite. Only REQ-14 additionally
needs `WALMART_STORE_ID`, which is still unset (count `0`, never a value).

That reframes the deferral usefully. It was recorded as *"the store pin and the
restart"*, one decision. It is two, and three of the four requirements are on the
cheaper side of it.

## Applying the milestone's thesis to the milestone

v0.2's subject is one shape: *the system stating something it had not established.*
The fair test of this milestone is whether its own records commit that shape. Mostly
they refuse to, at a standard I could not fault. Once, they commit it exactly.

slip. 05-04 renumbered `0.`→`2.` and shifted the rest. So the one edit to a criterion

### Where the milestone commits its own defect

**`CHANGELOG.md` — the file that ships to a stranger — states behaviour the code does
not have.** Lines 45-53, under `## [0.2.0]`:

> *"a shipping cost that cannot be resolved produces UNKNOWN instead of a pass.
> Measured against the built tree: … Nintendo and Amazon stop being able to page …
> and Walmart is *not demonstrated*"*

Falsified by execution, not by reading:

```
$ .venv/bin/python  # _verdict_from_html over the real captures, max_price=80
nintendo  price=54.99 shipping=None total=None  | forced IN_STOCK -> alertable=True
gamestop  price=54.99 shipping=6.99 total=61.98 | forced IN_STOCK -> alertable=True
```

Nintendo — the only entry in `config/products.yaml` listing the GO Plus + at $54.99
MSRP with no marketplace attached, the single best restock signal this project has —
resolves no shipping and **alerts anyway**. An unresolvable shipping cost produces a
pass. The sentence in the changelog is the rule Dan revoked on 2026-08-11.

The mechanism is dull and that is the point. `CHANGELOG.md` was last touched at
`ac8155b` on 2026-08-10. The reversal shipped in five commits on 2026-08-11
(`717015b`…`b9e39bc`). Nothing carried it across. `## [Unreleased]` still reads
`Nothing yet.` while an unreleased, user-visible alerting change is sitting in the
tree. And `pyproject.toml` declares `0.2.0` with `tests/test_packaging_metadata.py`
binding that heading to it, so `[0.2.0]` is a description of the current code, not a
frozen historical entry — nor could it be frozen: 0 tags, 0 refs, PyPI 404.

Four things make this a gap rather than a nit:

1. **It is the milestone's named defect** — a claim published without the measurement
   behind it — in the milestone's own published output.
2. **It is in the artefact REQ-19 was written about.** `MANIFEST.in` puts it in the
   sdist; `[project.urls] Changelog` points every installer at it. REQ-19's founding
   sentence is *"Nothing reads the CHANGELOG body."* Something reads it now, and the
   first thing to go wrong in it after the gate landed was not something the gate can
   see. Criterion 4 is met on its own terms — I am not widening it — but what it bought
   is narrower than the milestone's thesis, and that is worth saying out loud.
3. **Everywhere else got it right.** README.md carries the reversal and even names the
   reopened hole to a stranger's face. REQUIREMENTS.md, ROADMAP.md, STATE.md,
   `retailer-evidence.md`, `06-VERIFICATION.md` and two source files all record it.
   One file was missed, and it is the one that ships.
4. **Nobody caught it.** Not 06-07, not 06-06's close, not the phase verifier, not
   STATE.md. Every other outstanding item in this milestone is written down somewhere.
   This one is not written down anywhere, which is what separates a gap from debt.

## REQ-17's revision, assessed on its own

Dan reversed the second half of REQ-17 mid-phase, knowingly reopening the hole the
requirement was written to close: *"I think where we don't know just send it."* The
question this audit was asked is whether that is recorded honestly and whether the
original text survived.

**The original text survived, byte for byte** — checked across all of REQ-14…REQ-20
against `4994c7d`, and the ROADMAP criterion against the scoping commit. The reversal
is recorded *beside* the original in Phase 3.1's format, which is this project's house
form for a user reversing a decision, and the record is explicit that this is a
different act from an agent rewording a criterion so finished work looks successful.
The cost was measured before he chose and written down after: two of four product
watches silenced under the strict rule, all four alerting under the reversal, Walmart
moving off *not demonstrated* on an unchanged measurement.

The mitigation is a field, not a paragraph: `price: $54.99   shipping: unknown`, the
same shape either way, with no delivered total stated in either body — you cannot add
a number to `unknown`. Read out of `boty/notify.py:156` and pinned by the first
assertions ever made about `send_restock`'s body.

So: honestly recorded in six of seven places, and the seventh is the gap above. The
requirement is **partial** — its behaviour is complete as revised, its public record
is not.

## The recurring defect: `.planning/` markup — debt, gap, or deferred?

**Correctly deferred, and it should stay logged rather than be built now.** Three
reasons, and I checked each rather than accepting the argument:

- **REQ-19's own subject is "files that ship to a stranger", and `.planning/` does not
  ship.** `MANIFEST.in` carries `prune .planning`, and the sdist-pruning test passes.
- **The narrow scope is argued structurally and the argument is itself gated** — a
  tree-scoped markup rule would redden its own definition, because the module must
  contain the shapes it forbids, and
  `test_this_gate_would_redden_its_own_definition_if_it_were_scoped_to_the_tree`
  passes. The widening mechanism is named in place.
- **The instance was found by measurement and recorded with its SHA**, not smoothed
